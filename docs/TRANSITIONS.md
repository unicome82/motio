# 10 Transitions — 구현 기록

## 범위와 변경 파일

10_TRANSITIONS를 구현했다. 일곱 실험의 hash 탐색·이전/다음·목록 링크를 유지하고 UI 전환과 초기화 중 정리를 보완했다. 11 종합 QA는 진행하지 않았다. 기존 레이아웃·색상·SCSS는 변경하지 않아 CSS 컴파일도 실행하지 않았다.

- `js/core/view-transition.js` 추가: GSAP의 200ms 선형 진입 페이드, 빠른 전환 취소, 오래된 완료 콜백 무시, 동작 줄이기·탭 숨김·미로딩 시 즉시 표시, 종료 정리.
- `js/core/scene-manager.js` 수정: 초기화 대기 중인 장면과 입력도 보유하고 이탈 시 즉시 정리한다. 활성/대기 자원의 정리를 한 번만 수행하며 오래된 초기화가 끝나도 최신 장면을 건드리지 않는다.
- `js/app.js` 수정: 라우트 변경 시 전환 취소 → 이전 장면 정리 → 새 화면 구성 → 진입 페이드 연결. 이전/다음 링크에 대상 실험 이름 추가, 본문 건너뛰기가 현재 URL hash를 변경하지 않도록 수정. 설정·About 전환 안내 갱신.
- `index.html` 수정: TRANSITIONS / 10 표기.
- `tests/transitions.mjs` 추가: 전환 제어의 경합·대체 동작 검사.
- `tests/scene-integration.mjs` 추가: 실제 일곱 장면과 Matter 엔진을 연결한 100회 전환 및 초기화 중 정리 검사.
- `docs/TRANSITIONS.md` 추가: 이 기록.

## 동작

최초 진입은 즉시 표시한다. 이후 라우트 이동은 기존 장면을 즉시 정리하고 새 화면에만 200ms 페이드를 적용한다. 이전 화면을 붙잡는 퇴장 지연은 없다. 시뮬레이션 계산은 SceneManager의 고정 스텝으로 계속 관리하며 GSAP는 main의 opacity만 조절한다. 레이아웃 이동·배경 효과·물리 연출은 추가하지 않았다.

빠르게 이동하면 진행 중 tween을 종료하고 opacity를 복원한다. 동작 줄이기 설정이 켜져 있거나 문서가 숨겨졌거나 GSAP를 불러오지 못했다면 애니메이션 없이 표시한다. 실행 도중 동작 줄이기 변경과 탭 숨김도 진행 중 전환을 취소한다.

hash router와 실제 링크를 유지하므로 직접 주소·새로고침·브라우저 기록 탐색을 위한 구조를 그대로 사용한다. 잘못된 route는 기존 찾을 수 없음 화면을 표시한다. 본문 건너뛰기는 hash를 #main으로 바꾸지 않고 현재 화면의 main에 포커스한다. 따라서 건너뛰기 후 새로고침에도 실제 실험 route가 유지된다.

CSS 모듈의 import 자체를 네트워크 수준에서 취소하는 것은 아니다. 세대 번호와 AbortSignal로 오래된 로딩 결과의 활성화를 막고, 이미 만든 장면·입력 자원은 바로 정리한다. 이전 장면을 정리한 뒤 새 장면을 시작하며 시뮬레이션 RAF는 하나만 유지한다. GSAP의 UI ticker는 물리 스케줄러와 별개다.

## 실제 검증

Node v22.23.4에서 실행:

```sh
node tests/transitions.mjs
node tests/scene-integration.mjs /private/tmp/motio-matter-0.20.0.cjs
```

- 실제 일곱 장면을 순환해 100회 mount/update/render/destroy. Matter 장면은 실제 0.20.0 엔진을 사용했다. 매번 RAF 1개·ResizeObserver 1개 유지, 종료 후 모두 해제 확인.
- 지연된 init에서 이동 시 이전 장면 destroy와 입력 abort가 새 장면 init 전에 일어남을 확인. 늦게 끝난 init은 최신 장면을 중지하지 않고 destroy를 중복 호출하지 않는다.
- 200ms GSAP 호출 계약, 100회 연속 페이드 전환 취소, 오래된 콜백 무시 검사 통과.
- 동작 줄이기 실시간 변경, 숨김 상태, GSAP 미로딩 대체 동작과 종료 후 리스너 해제 검사 통과.
- 기존 Foundation 라우터 최초 hash·hashchange 검사와 모든 물리 장면 회귀 검사 통과.
- 수정 JavaScript 구문 검사 통과.

DOM/Canvas/RAF/GSAP는 제어 가능한 대역을 사용했다. 실제 브라우저 GSAP 렌더링, 기록 API를 통한 뒤로/앞으로, 직접 새로고침과 포커스의 실기기 동작을 검증한 것은 아니다. 실제 장면과 물리 모델은 가져와 실행했지만 브라우저 메모리 프로파일링을 대신하지 않는다.

## 남은 수동 확인

1. 1440/1024/390/320 화면에서 200ms 전환과 기존 배치가 유지되는지 비교한다.
2. 일곱 직접 hash 주소 진입·새로고침·이전/다음·목록·홈 CTA와 브라우저 뒤로/앞으로를 확인한다.
3. 실험 링크를 빠르게 누르고 초기화·장면 이동을 섞어 이전 입력·엔진이 남지 않는지 확인한다.
4. Tab·본문 건너뛰기·메뉴 Escape·이전/다음 링크의 읽기 이름을 확인한다.
5. 시스템 동작 줄이기를 전환 중 변경하고, 탭 숨김·복귀 및 GSAP CDN 차단 상태에서 내용이 즉시 보이는지 확인한다.
6. 실제 모바일 터치·회전·센서 권한과 장시간 메모리·프레임 시간을 확인한다.

브라우저·실기기 시각 검증은 이번 환경에서 실행하지 못했다. 11 종합 QA는 진행하지 않았다.
