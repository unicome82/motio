# 08 Chain Reaction — 구현 기록

## 범위와 변경 파일

미구현 상태였던 08_CHAIN을 구현했다. 이미 구현한 09 Sandbox와 다른 실험은 유지한다. 이제 일곱 실험이 연결되어 있으나 10 전환 효과 통합이나 11 종합 QA는 진행하지 않았다. 기존 Matter.js 0.20.0 지연 로더·단일 RAF·고정 1/60 업데이트·반응형 화면을 재사용했다. SCSS 변경이 없어 CSS 컴파일은 실행하지 않았다.

- `js/physics/chain-world.js` 추가: 공·삼각 경사면·바닥·경계·도미노, 두 가지 프리셋, 재생 가능한 엔진 초기화와 정리.
- `js/scenes/chain.js` 추가: 실제 물리 좌표의 플랫 렌더링, 프리셋 변경·재생·넘어진 개수 안내, pause/resize/destroy.
- `js/core/scene-manager.js` 수정: Chain 지연 로더 연결.
- `js/app.js` 수정: 프리셋·재생 버튼·설명, 재생 시 공통 관리자 재개, 홈·목록·About의 구현 상태 갱신.
- `index.html` 수정: CHAIN REACTION / 08 표기.
- `tests/chain.mjs` 추가: 실제 Matter 엔진의 연쇄 충돌·반복성·정리 검사.
- `docs/CHAIN.md` 추가: 이 기록.

## 동작

`#chain` 진입 시 공이 중력에 의해 경사면을 내려와 첫 도미노를 밀며 연쇄 반응을 시작한다. 도미노를 순서대로 회전시키거나 강제로 쓰러뜨리는 코드는 없다. GSAP·CSS 모션으로 물리 동작을 대신하지 않는다.

기본 프리셋은 11개, 촘촘한 프리셋은 13개 도미노다. 선택 변경 시 해당 배치를 재생성하며 일시 정지 상태는 유지한다. 다시 재생은 현재 프리셋을 재생성하고 공통 SceneManager를 재개한다. 초기화 역시 현재 선택된 프리셋을 유지한다. 자동 반복이나 별도 타이머는 없다.

넘어진 개수는 도미노 각도가 약 37도를 넘은 경우로 판정하고 값이 바뀔 때만 상태 영역을 갱신한다. 직접 물체를 잡아 편집하는 기능은 제공하지 않으며 프리셋과 재생·정지 버튼을 키보드로 조작할 수 있다.

동일한 논리 크기 800×500에서 계산하므로 해상도가 달라도 초기 배치와 충돌 조건이 같다. 화면 크기 변경은 중앙 정렬된 비례 렌더링만 조정하며 진행 중 물리 상태를 보존한다. 좁은 화면에서는 전체 연쇄를 보여주므로 도미노가 작아지는 시각적 제약이 있다. 모서리 비율이 다른 캔버스에는 여백이 생긴다.

## 실제 검증

Node v22.23.4, 기존 임시 파일의 Matter.js 0.20.0으로 검사했다.

```sh
node tests/chain.mjs /private/tmp/motio-matter-0.20.0.cjs
```

- 두 프리셋 각각 세 번 × 1,200스텝, 총 7,200스텝에서 매번 모든 도미노가 넘어짐을 확인했다.
- 각 재생의 최종 위치·각도가 0.001 오차 이내로 일치했다. 이는 같은 Node/Matter 실행 환경에서의 재현성이다.
- 실제 collisionStart 이벤트 확인, 유한 좌표 및 정상 프리셋의 좌우·바닥 경계 이탈 없음 확인.
- 정지 시 엔진 시간 유지, 프리셋 교체, 재생 시 시간 초기화, resize 시 진행 상태 유지, Canvas 그리기 확인.
- 100회 장면 생성·종료, 엔진·body 정리 및 종료 후 재생 이벤트 해제 확인.
- Foundation·Gravity·Elastic·Magnetism·Wave·Cloth·Sandbox 회귀 검사와 수정 JavaScript 구문 검사 통과.

Canvas·DOM 일부는 대역으로 검사했다. 실제 브라우저 시각 품질·기기 성능·메모리·입력 검증을 대신하지 않는다. 임의의 변경 배치나 극단적인 속도에서도 충돌 누락이 없다고 보장하지 않는다.

## 수동 확인 절차와 남은 사항

로컬 HTTP 서버에서 `index.html#chain`에 접속한다. Matter.js CDN 접근이 필요하다.

1. 공이 경사면을 내려와 전체 도미노를 순서대로 넘어뜨리는지 확인한다.
2. 두 프리셋 변경, 정지·재개·초기화·다시 재생과 상태 개수를 확인한다.
3. 정지 중 프리셋 변경 뒤 재개, 정지 중 다시 재생, Tab·Enter·Space 버튼 조작을 확인한다.
4. 재생 중 화면 크기 변경·모바일 회전에서 물리 진행이 유지되는지 확인한다.
5. 1440/1024/390/320 화면의 배치·색상·도미노 가독성을 레퍼런스와 비교하고 프레임 시간·메모리를 측정한다.

브라우저·실기기 확인은 실행하지 못했다. 10 이후 단계는 진행하지 않았다.
